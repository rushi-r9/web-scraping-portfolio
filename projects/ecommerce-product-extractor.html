Portfolio case study · 01

E-commerce product data extractor

Turn product catalogue pages into normalized, export-ready records for research and comparison.

Runnable demoSelf-initiated demonstrationSynthetic local fixtures

The problem

Product research often starts with information scattered across many catalogue pages. A team may need a consistent product list before pricing analysis, merchandising review, or catalogue cleanup can begin.

The proposed solution

The demonstration parser reads paginated product-card HTML fixtures, normalizes text, validates required identifiers and URLs, removes duplicate SKUs, and exports one clean dataset. The included fixture pages are local and synthetic so the full run is reproducible without contacting a retailer.

What it can extract or produce

  • SKU
  • Product name
  • Price and currency
  • Category
  • Availability
  • Rating
  • Description
  • Product URL

Implemented features

  • Multi-page traversal through rel="next" links
  • SKU-based deduplication
  • Required-field validation and optional-field missing-value counts
  • CSV, JSON, SQLite, and optional XLSX export
  • Execution logs and a machine-readable quality report

Technology

Python 3html.parsercsv / jsonsqlite3openpyxl (optional)

Only tools used by the corresponding included script are listed here. Browser automation and external request libraries are not implied.

Sample results

These sample business records are synthetic and generated for demonstration. They are not client data or records collected from a live third-party website.

Representative exported fields include stable identifiers, normalized text, source references, and blank values where optional information is absent. The exact schema for this project is documented in demo_kit/schemas.py.

$ python scraper.py --dataset products --verbose [INFO] Reading local fixture pages [INFO] Normalizing fields and checking required values [INFO] Removing duplicate record identifiers [INFO] Exporting CSV / JSON / SQLite / optional XLSX

Output formats

  • CSV for spreadsheets and simple data pipelines
  • JSON for programmatic integrations
  • SQLite for local querying and review
  • XLSX when the optional openpyxl package is installed

Data quality

The current demonstration normalizes whitespace, validates required fields, removes duplicate IDs and writes a report of missing optional values. It does not invent absent values. A live engagement would add source-specific checks and agreed acceptance samples.

Business value

A business could use a permitted product dataset as the starting point for catalogue auditing, assortment research, internal reporting, or price comparisons. The demo shows the transformation pattern; it does not provide live retailer data.

Every file linked below is generated by the downloadable demo kit. The outputs are reproducible on the included local HTML fixtures.

Limitations

No live retailer connector, JavaScript rendering, anti-bot handling, proxy rotation, or production scheduler is included. All fixture records are synthetic.
