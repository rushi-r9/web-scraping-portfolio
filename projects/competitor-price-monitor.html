Portfolio case study · 05

Competitor price monitoring prototype

Compare two snapshots to identify price movement and availability changes in a small sample catalogue.

PrototypeSelf-initiated demonstrationSynthetic local fixtures

The problem

A single price snapshot cannot show whether a product became cheaper, more expensive, or unavailable. Teams need comparable historical observations.

The proposed solution

The included script groups synthetic observations by SKU, sorts them by observation date, compares the latest two records, calculates absolute and percentage changes, and writes CSV, JSON, and a concise Markdown report.

What it can extract or produce

  • SKU
  • Product name
  • Previous price
  • Current price
  • Change amount
  • Change percent
  • Availability before / after
  • Observation date
  • Source URL

Implemented features

  • Historical observation grouping
  • Price movement calculations
  • Availability transition detection
  • CSV / JSON change report
  • Source URL retained for review

Technology

Python 3csvcollectionsjsonpathlib

Only tools used by the corresponding included script are listed here. Browser automation and external request libraries are not implied.

Sample results

These sample business records are synthetic and generated for demonstration. They are not client data or records collected from a live third-party website.

Representative exported fields include stable identifiers, normalized text, source references, and blank values where optional information is absent. The exact schema for this project is documented in demo_kit/schemas.py.

$ python scraper.py --dataset all --verbose [INFO] Reading local fixture pages [INFO] Normalizing fields and checking required values [INFO] Removing duplicate record identifiers [INFO] Exporting CSV / JSON / SQLite / optional XLSX

Output formats

  • CSV for spreadsheets and simple data pipelines
  • JSON for programmatic integrations
  • SQLite for local querying and review
  • XLSX when the optional openpyxl package is installed

Data quality

The current demonstration normalizes whitespace, validates required fields, removes duplicate IDs and writes a report of missing optional values. It does not invent absent values. A live engagement would add source-specific checks and agreed acceptance samples.

Business value

With authorized recurring observations, this pattern could support pricing reviews, catalogue checks, and internal competitor reporting. Decisions should be reviewed against source context and collection timestamps.

Project evidence and reproduction

Run the corresponding dataset command in the demo kit, then inspect the generated CSV, JSON, SQLite database, and optional XLSX workbook. The project bundle contains the fixtures and reproduction instructions.

Limitations

The snapshots are synthetic and only two observations are compared. No live collection, notification service, dashboard, tax/shipping normalization, or continuous monitoring is deployed.
